# 报销材料管理系统设计规格

日期：2026-05-21

## 1. 系统定位

本系统是一个企业内部使用的 BS 架构报销材料管理平台，核心目标是解决报销材料收集、结构化、归档、查询和导出的繁琐问题。

系统第一阶段不做审批流、不做付款管理、不做 OCR、不对接外部财务系统。重点是让员工能规范提交材料，让管理员能高效整理、导出和归档。

## 2. 角色与权限

### 员工

员工可以：

- 登录系统。
- 新建报销记录。
- 保存草稿。
- 上传支付凭证。
- 选填订单截图。
- 选填发票。
- 填写金额、用途分类、用途说明和支付时间。
- 提交报销记录。
- 查看自己的报销记录。

员工只能访问自己的数据。员工只能编辑草稿状态的记录。

### 管理员

管理员兼具财务整理和系统管理职责，可以：

- 管理用户。
- 管理用途分类。
- 查看全部报销记录。
- 按人员、时间、分类、状态筛选记录。
- 创建和维护报销批次。
- 导出 Excel 清单。
- 下载附件压缩包。
- 归档报销记录。
- 填写管理员备注。

## 3. 报销记录状态

状态流为：

```text
草稿 -> 已提交 -> 已归档
```

### 草稿

员工可编辑、删除、补充附件。

### 已提交

员工不可修改。管理员可查看、筛选、加入批次和导出。

### 已归档

表示材料已完成整理并进入历史归档。归档后的记录默认不可再修改。

## 4. 报销记录字段

每条报销记录包含：

- 员工：系统自动关联。
- 金额：必填。
- 用途分类：必填，只能选择启用分类。
- 用途说明：必填。
- 支付时间：必填。
- 支付凭证：必填，支持多张。
- 订单截图：选填，支持多张。
- 发票：选填，支持多张。
- 状态：草稿、已提交、已归档。
- 管理员备注：选填。
- 创建时间。
- 更新时间。
- 提交时间。
- 归档时间。

附件类型固定为：

```text
payment_voucher
order_screenshot
invoice
```

## 5. 用途分类

用途分类由管理员维护。员工只能选择启用中的分类，不能自定义分类。

分类字段包括：

- 分类名称。
- 是否启用。
- 排序。
- 备注。

初始分类建议：

- 办公用品。
- 差旅交通。
- 餐饮招待。
- 软件服务。
- 快递物流。
- 设备耗材。
- 其他。

## 6. 批次与导出

管理员可以创建报销批次，用于按月、项目或自定义周期整理材料。

批次能力包括：

- 添加已提交记录。
- 移除未归档记录。
- 导出 Excel 清单。
- 下载附件压缩包。
- 批量归档。

### Excel 字段

Excel 导出包含：

- 批次名称。
- 员工姓名。
- 部门。
- 金额。
- 用途分类。
- 用途说明。
- 支付时间。
- 支付凭证数量。
- 订单截图数量。
- 发票数量。
- 提交时间。
- 管理员备注。
- 附件目录路径。

### 附件包结构

附件压缩包结构为：

```text
报销批次-2026-05/
  张三/
    001-办公用品-128.00/
      支付凭证/
      订单截图/
      发票/
  李四/
    002-差旅交通-86.50/
      支付凭证/
      发票/
```

## 7. 系统模块

### 前端 Web

前端模块包括：

- 登录页。
- 员工首页。
- 报销记录列表。
- 新建和编辑报销记录页面。
- 附件上传组件。
- 管理员后台。
- 用户管理。
- 分类管理。
- 批次管理。
- 导出管理。

### 后端 API

后端模块包括：

- 认证与会话。
- 用户管理。
- 分类管理。
- 报销记录管理。
- 附件上传与下载。
- 批次管理。
- Excel 导出。
- 附件压缩包导出。

### 数据库

核心数据表包括：

- users。
- reimbursement_records。
- reimbursement_attachments。
- expense_categories。
- reimbursement_batches。
- reimbursement_batch_items。

### 文件存储

第一阶段使用本地文件存储：

```text
storage/
  reimbursements/
    {record_id}/
      payment_voucher/
      order_screenshot/
      invoice/
```

后续可以迁移到 MinIO、S3 或阿里云 OSS。业务层应通过文件存储接口访问文件，避免业务代码绑定具体存储实现。

## 8. 数据流

### 员工提交流程

1. 员工登录。
2. 创建报销草稿。
3. 填写金额、分类、说明和支付时间。
4. 上传至少一张支付凭证。
5. 选填订单截图和发票。
6. 保存草稿或提交。
7. 提交后记录进入已提交状态。

### 管理员整理流程

1. 管理员登录后台。
2. 筛选已提交记录。
3. 创建或选择报销批次。
4. 将记录加入批次。
5. 导出 Excel 清单。
6. 下载附件压缩包。
7. 确认整理完成后批量归档。

## 9. 异常与约束

系统必须保证：

- 未登录用户不能访问业务页面。
- 员工不能访问他人记录。
- 员工不能修改已提交或已归档记录。
- 提交时必须校验金额、分类、说明、支付时间和支付凭证。
- 管理员不能归档未加入批次的记录。
- 禁止上传非图片或非 PDF 类型附件。
- 限制单个附件大小，默认 10MB。
- 导出时如果附件文件缺失，Excel 中必须标记异常，不能静默忽略。

## 10. 技术路线

推荐技术栈：

- 前端：Vue 3、TypeScript、Vite、Element Plus。
- 后端：Java Spring Boot。
- 数据库：MySQL。
- 文件存储：本地文件系统起步，后续支持对象存储。
- Excel 导出：Apache POI。
- 压缩包导出：Java ZipOutputStream。

该路线适合企业内部系统，部署稳定，维护人员容易招聘，生态成熟。

## 11. 分期实施

### 第一期：核心可用

目标：员工能提交材料，管理员能导出和归档。

范围：

1. 项目初始化。
2. 登录认证。
3. 用户管理。
4. 用途分类管理。
5. 报销记录 CRUD。
6. 附件上传。
7. 草稿、提交、归档状态流。
8. 管理员全量查询。
9. 批次管理。
10. Excel 导出。
11. 附件压缩包导出。

### 第二期：管理增强

目标：提升长期使用效率。

范围：

1. 高级筛选。
2. 管理员备注增强。
3. 附件在线预览。
4. 操作日志。
5. 数据统计。
6. 批量操作优化。

### 第三期：智能化

目标：减少手工录入。

范围：

1. OCR 识别金额。
2. OCR 识别商户。
3. OCR 识别支付时间。
4. OCR 识别发票信息。
5. 人工纠错确认。

### 第四期：企业集成

目标：接入企业已有系统。

范围：

1. 企业微信或钉钉登录。
2. 财务系统 API 对接。
3. 对象存储迁移。
4. 审计报表。
5. 自动备份策略。

## 12. 第一期验收标准

第一期完成时必须满足：

- 员工可以登录。
- 员工可以新建草稿。
- 员工可以上传支付凭证。
- 员工可以选填订单截图和发票。
- 员工可以填写金额、分类、用途说明和支付时间。
- 员工可以提交记录。
- 管理员可以查看所有提交记录。
- 管理员可以维护用户。
- 管理员可以维护用途分类。
- 管理员可以创建批次。
- 管理员可以将已提交记录加入批次。
- 管理员可以导出 Excel。
- 管理员可以下载附件压缩包。
- 管理员可以归档记录。

## 13. 明确不做

第一期明确不做：

- 审批流。
- 报销付款。
- OCR 自动识别。
- 外部财务系统对接。
- 企业微信或钉钉登录。
- 移动端 App。
